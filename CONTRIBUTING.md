# Contributing

## Workflow

1. Analyze the project (`/analyze`)
2. Create a plan (`/plan`)
3. Implement changes
4. Run tests (`/test`)
5. Review the result (`/review`)
6. Check security (`/security`)
7. Prepare commit (`/commit`)

## Code Style

- Follow `.editorconfig`
- Keep code modular
- Avoid unnecessary dependencies
- Document non-obvious decisions

## Pull Requests

- One logical change per PR
- Update documentation if needed
- Ensure tests pass before merging
